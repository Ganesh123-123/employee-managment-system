# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic bug: converts to integer minutes first (`int(total_seconds / 60)`) and checks `minutes > 10`. At 10 min 1 sec (`09:40:01`), integer minutes is 10, so it returns `0` instead of `10` mandated by R2. Also constructs naive datetime ignoring IST timezone and midnight rollovers. | Input shift `09:30`, punch-in `09:40:01`. Expected `10`, received `0`. | Computed elapsed seconds directly against IST shift start (`diff_seconds > 600`), and took floor whole minutes `int(diff_seconds // 60)` when late. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (round half to even) rather than round half-up required by R4. Also failed to truncate instants to whole seconds before computation. | An interval yielding fractional half (e.g., 2.125 or values with floating-point inaccuracies like 9.11666...) rounds to even instead of up. | Truncated seconds before division, calculated duration using `Decimal`, and applied `ROUND_HALF_UP` to 2 decimal places. |
| 3 | `compute_overtime` (lines 44-47) | Date assumption and threshold bugs: sets shift end on `date_str` even for overnight shifts (`shift_end <= shift_start`), causing ~24 hours of bogus overtime across midnight. Also counts any positive minutes instead of enforcing the 30-minute minimum required by R3. | Overnight shift 22:00-06:00 on 2026-07-06 punched out 2026-07-07 06:40 reports 1480 minutes overtime. Day shift punched out 5 minutes late reports 5 minutes instead of 0. | Added overnight check rolling shift end to `date + 1 day`, and returned overtime only if elapsed minutes >= 30, else 0. |
| 4 | `create_employee` (lines 78-85) | Check-then-insert race condition: `find_one` followed by `insert_one` allows parallel requests to insert identical `emp_code`. Lacks unique DB index. Also returns `created_at` as raw Python datetime instead of epoch ms integer, and ignores rule that `shift_start != shift_end`. | Concurrent create requests with identical `emp_code` both yield 201. Input where `shift_start == shift_end` succeeds instead of returning 422. API response has string/ISO datetime. | Added unique index on `emp_code`, handled `DuplicateKeyError` to return 409, validated shift difference in Pydantic with 422, and serialized `created_at` to epoch milliseconds. |
| 5 | `list_employees` (lines 89-96) | Off-by-one pagination bug: `skip = page * page_size` skips the first page entirely (`page=1` skips 20 records). Also `total = count_documents({})` counts the entire collection ignoring the `department` filter, missing sort by `emp_code` ascending, and fails to serialize `created_at` to epoch ms. | Requesting `page=1` omits the first 20 employees. Filtering by `department="Sales"` returns total count of all company employees. | Changed skip calculation to `(page - 1) * page_size`, applied filter `q` to `count_documents(q)`, added `.sort("emp_code", 1)`, and formatted records. |
| 6 | `health` (lines 72-74) | Returns hardcoded `{"status": "ok"}` without verifying database connectivity. Contract requires 503 if MongoDB is unreachable. | Stop MongoDB and call `GET /health`. Returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command("ping")` inside a try/except block; raises `HTTPException(503)` if ping fails. |
| 7 | `punch_in` (lines 99-122) | Concurrency race condition: check-then-insert allows duplicate punches for the same employee-date under load. Also crashes with HTTP 500 (`TypeError`) if employee is missing. Calculates date in system local time instead of IST (violating R1) and fails to handle overnight shift date attribution. Instants not truncated to whole seconds. Leaks MongoDB internal `_id` as `"id"`. | Concurrent punch-ins create multiple records for same date. Calling with non-existent `emp_code` returns 500. Overnight punch-in at 00:15 attributed to current day instead of previous shift start day. | Added unique compound index `(emp_code, date)` and caught `DuplicateKeyError` returning 409. Verified employee existence returning 404. Handled IST conversion and overnight shift rule (R1), truncated instants to whole seconds, and removed `_id` from output. |
| 8 | `list_attendance` (lines 125-150) | In-memory sort and unindexed query: loads all matching logs into Python with `list(db.attendance_logs.find(q))` and sorts in Python, causing high memory usage and query timeout on 100k records. Lacks secondary sort by `emp_code` ascending. Fails to validate `date_from > date_to` (must return 422). Leaks `_id` as `id` string. | Requesting with `date_from="2026-07-10"` and `date_to="2026-07-05"` returns 200 instead of 422. Testing against 100k docs triggers high memory consumption. | Handled sorting and pagination directly in MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by a compound index. Added validation raising 422 when `date_from > date_to`, and formatted timestamps as epoch ms. |
| 9 | Database & Timezone Configuration (lines 20-25) | `MongoClient` initialized with default `tz_aware=False`, returning naive UTC datetimes that corrupt timezone arithmetic. Also `load_dotenv()` without `override=False` can allow local `.env` values to overwrite container/grader environment variables. Missing index initialization at startup. | Datetime calculations produce ambiguous comparisons. Environment variables injected by test runners get overridden by local `.env`. | Configured `load_dotenv(override=False)`, initialized `MongoClient(..., tz_aware=True, serverSelectionTimeoutMS=2000)`, and created all required indexes idempotently in a FastAPI `lifespan` handler. |
| 10 | Input Validation on Models (lines 53-68) | Pydantic models lack OpenAPI constraints: `emp_code` allows arbitrary strings, `email` lacks regex pattern, `punched_at` accepts seconds (e.g. 1700000000) or floats/strings, and `status` accepts invalid attendance values (e.g. "ABSENT" on punch-in). | Sending `{"emp_code": "bad", "punched_at": 1700000000, "status": "ABSENT"}` returned 201 instead of 422 validation failure. | Implemented strict Pydantic models matching OpenAPI schemas: pattern `^EMP\d{4,6}$`, strict `ge=100000000000` integer milliseconds for timestamps, and restricted `status` literals. |

## Items examined and determined NOT to be defects
- **India Standard Time Definition (`IST = timezone(timedelta(hours=5, minutes=30))`):** India does not observe Daylight Saving Time (DST); IST remains a constant UTC+05:30 offset year-round, so a fixed `timezone` offset is accurate.
- **Natural Composite Key `(emp_code, date)`:** Attendance logs do not expose or require a surrogate primary key. Addressing records naturally by `(emp_code, date)` aligns directly with the business specification and `DATA_MODEL.md`.
- **Derived Fields Stored Autoritative:** Not recomputing `work_hours`, `late_minutes`, and `overtime_minutes` during analytics queries is intentional per `DATA_MODEL.md`, as analytics must read the authoritative values written during punch events or regularization.
